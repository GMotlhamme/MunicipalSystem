# Updates Based on Lecturer Feedback

## 1. Introduction

During Part 2 of the Municipal Services Application, I received a mark of 42/100. One of the main challenges I experienced was managing the development workload and keeping track of my Git commits.

Although I had been working on the required functionality, I did not commit all of my changes before the assessment. This affected the version of the application available for evaluation.

After reviewing the marking rubric, I focused on ensuring that the required data structures were implemented, connected to the application and tested properly.

## 2. Feedback Received and Improvements Made

| Assessment Area | Mark Received | Improvements Made |
|---|---|---|
| Main Menu | 27/30 | Maintained the existing navigation and ensured all three application features could be accessed correctly. |
| Stacks, Queues and Priority Queues | 4/15 | Implemented event-processing queues, recent-search history using a stack and a priority queue for upcoming events. |
| Dictionaries and Sorted Dictionaries | 4/15 | Used dictionaries to organise events by category and a SortedDictionary to organise events by date. |
| Sets | 3/10 | Implemented a HashSet to manage unique event categories and avoid duplicate category values. |
| Search Patterns and Recommendations | 9/30 | Improved event searching, filtering and recommendation functionality so users could find events based on their interests and search criteria. |

## 3. Addressing the Git Commit Issue

One of the biggest lessons from Part 2 was understanding the importance of version control throughout development.

I became overwhelmed while working on the application and failed to commit all my changes before the assessment. As a result, the submitted version did not fully reflect the work I had completed.

To address this, I focused on keeping track of my changes and ensuring the required functionality was included in the version prepared for the final submission.

This experience helped me understand that completing functionality is only one part of software development. Properly managing and submitting the code is equally important.

## 4. Testing the Improvements

After implementing the improvements, I manually tested the application to confirm that:

- Events could be displayed, searched and filtered.
- Event recommendations were displayed.
- Event categories were managed without unnecessary duplicates.
- The queue, stack and priority queue functionality worked.
- Navigation between the main application features continued working.

The tests were successful, and the application was able to perform the required operations.

## 5. Lessons Learned

The feedback helped me identify areas where I needed to improve both technically and in how I managed my development process.

I learned the importance of committing changes regularly, checking that the latest version of the application is available for assessment and testing functionality before submission.

I also improved my understanding of how different data structures can be used to organise and retrieve information efficiently.

## 6. Conclusion

Although my Part 2 results were disappointing, the feedback gave me a clearer understanding of what needed attention.

I used the assessment criteria to guide improvements to the application and ensure that the required data structures and features were functioning.

The experience also reinforced the importance of version control, time management and proper testing throughout software development.
